# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a vulnerability that could expose users, credentials, data, or deployment infrastructure. Report it privately through GitHub's security reporting channel when available, or contact the maintainer using the address listed on the GitHub profile.

Include the affected revision, reproduction steps, impact, and any suggested mitigation. Avoid including real secrets or private datasets.

## Supported scope

Security reports are welcome for the Python package, API, Docker configuration, CI/CD, dependency handling, Kafka/Redis integrations, and quarantine/alerting paths.

The detector is not a guarantee that poisoned data will be detected. Efficacy limitations should be reported as correctness/research issues unless they create a separate software security vulnerability.
